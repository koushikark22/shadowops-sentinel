# ShadowOps Sentinel

ShadowOps Sentinel is a Splunk Enterprise security monitoring app for detecting suspicious AI-agent activity in agentic operations environments.

The project models AI agents as non-human identities and correlates telemetry across agent activity, authentication, Model Context Protocol access, proxy/network events, Jira activity, Splunk audit activity, and detection output.

## Use Case

AI agents can interact with operational systems, tickets, internal tools, logs, and APIs. If an agent is manipulated through prompt injection, misconfiguration, excessive permissions, or credential misuse, it may access sensitive data or perform unauthorized actions.

ShadowOps Sentinel provides a Splunk-native investigation workflow for identifying rogue AI-agent behavior.

The sample event dataset is located at:

```text

```

The dataset contains simulated agentic operations telemetry across the following logical source types:

| Logical Source Type      | Description                                      |
| ------------------------ | ------------------------------------------------ |
| `shadowops:agent`        | AI-agent execution and activity events           |
| `shadowops:auth`         | Identity and authentication events               |
| `shadowops:jira`         | Ticketing and issue-tracking activity            |
| `shadowops:mcp_access`   | Model Context Protocol tool access events        |
| `shadowops:proxy`        | Network and proxy activity                       |
| `shadowops:splunk_audit` | Splunk audit activity                            |
| `shadowops:detection`    | Detection output generated by ShadowOps Sentinel |

## Install Splunk App

Copy the app folder into the Splunk apps directory.

### Windows

```powershell
Copy-Item -Recurse -Force ".\splunk_app\ShadowOpsSentinel" "C:\Program Files\Splunk\etc\apps\ShadowOpsSentinel"
& "C:\Program Files\Splunk\bin\splunk.exe" restart
```

### Linux/macOS

```bash
cp -R ./splunk_app/ShadowOpsSentinel $SPLUNK_HOME/etc/apps/ShadowOpsSentinel
$SPLUNK_HOME/bin/splunk restart
```

## Load Sample Data Into Splunk

Upload the file:

```text
sample_output/shadowops_events.jsonl
```

Recommended settings:

| Setting      | Value                               |
| ------------ | ----------------------------------- |
| Index        | `shadowops`                         |
| Input format | JSON                                |
| Source type  | `_json` or automatic JSON detection |

The uploaded metadata source type may appear as `_json`. The application extracts the logical source type from the nested JSON field:

```text
event.sourcetype
```

Dashboard searches use:

```spl
index=shadowops
| spath path=event.sourcetype output=real_sourcetype
```

## Validation Queries

### Validate Event Count

```spl
index=shadowops
| stats count
```

Expected result:

```text
513
```

### Validate Logical Source Types

```spl
index=shadowops
| spath path=event.sourcetype output=real_sourcetype
| stats count by real_sourcetype
| sort real_sourcetype
```

Expected logical source types:

```text
shadowops:agent
shadowops:auth
shadowops:detection
shadowops:jira
shadowops:mcp_access
shadowops:proxy
shadowops:splunk_audit
```

### Validate Rogue-Agent Detection

```spl
index=shadowops
| spath path=event.sourcetype output=real_sourcetype
| search real_sourcetype="shadowops:detection"
| spath
| table _time event.detection_name event.severity event.risk_score event.agent_id event.user event.summary
```

Expected detection:

```text
Detection name: Shadow Agent Prompt Injection Exfiltration
Severity: critical
Risk score: 94
Agent: productivity-copilot-local
```

## Detection Scenario

The included detection scenario represents a suspicious AI-agent sequence involving:

1. Access to a prompt-injection ticket.
2. Sensitive Splunk search activity.
3. External webhook communication.
4. Critical detection generation with a high risk score.

The detection is represented as a normalized `shadowops:detection` event and displayed in the Splunk dashboard.
